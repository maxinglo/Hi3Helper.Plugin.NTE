# 版本预下载

0.13.0 接入 Collapse 的 `GetApiPreloadGameVersion`、`IsGameHasPreload`、`GameInstallerKind.Preload` 和 `StartPreloadAsync`。用户在已安装的异环页面使用宿主提供的预下载入口。

0.13.1 修复正式发布版本高于预下载版本时的缓存复用，并为普通更新启用官方差分下载。更新计划以实际剩余网络字节选择直接差分、多个连续差分或完整资源。

## 官方状态与下载量

2026-11-04 实时核验的国服正式分支为 `PC_140 / 1.4.18`；配置以 `PreReleaseStatus=start` 公布 `PC_150 / 1.5.0`。本机官方启动器的公开 Patcher 配置和预下载清单与该结果一致。版本与分支动态读取，不硬编码为这两个值；其他区服也必须实际公布有效配置才提供入口。

当前清单有 334 个基础安装文件，36 个变化文件，其中 9 个适用官方差分包。假定当前正式版文件完整且匹配清单，计划预下载 **11,723,251,704 字节，约 10.92 GiB**；下载全部完整变化文件则为 50,422,620,669 字节。实际计划会检查源文件是否存在、大小是否匹配；缺失文件可能需要下载完整资源。已安装的可选基础资源继续遵循现有版本保留规则。

当日实时 CDN 核验包含经 MD5 校验的 33,756,839 字节差分包及 3 字节 Pak 范围样本。

2026-11-05 正式版为 `PC_150 / 1.5.3`。从完整的 1.4.18 基础资源更新，完整变化文件总计 50,532,024,120 字节，官方直接差分方案为 **11,923,529,736 字节，约 11.10 GiB**。正式差分清单同时保留 `1.4.18 → 1.5.0` 和 `1.5.0 → 1.5.3` 的边，9 个预下载补丁可以继续使用。本机原生插件只读核验得到的剩余下载量为 **1,421,257,306 字节，约 1.32 GiB**；该数字取决于实际安装和缓存状态，不是所有用户的固定下载量。

0.13.0 只查找能直接生成正式版的完整缓存差分，且普通更新不主动下载差分，因而会在上述版本变化中错误地转向约 50.5 GB 的完整资源下载。0.13.1 的清单回归固定保存了这次发布的资源身份及公开差分清单，防止该问题再次出现。

## 状态与缓存

- 仅接受明确的 `start` 状态、安全分支名，以及高于正式版的预下载版本。未安装、当前版本仍需更新或共享目录需要激活目标区服时不开放预下载。
- 开始下载前重新获取官方状态。配置、目标版本、资源清单的 `listHash` 与差分清单的 `diffHash` 必须一致。
- 缓存位于 `<游戏目录>/.collapse_nte_preload/<AppId>/<MD5>.<大小>`，按应用和内容隔离。相同内容也可以跨预告版本复用。
- 续传使用与普通下载相同的 `.tmp` 和 `.tmp.identity`，支持取消、HTTP Range、块资源、Pak 范围下载、CDN 回退及现有调度和磁盘预算。
- 下载期间只写缓存。预下载完成不会调用版本设置、官方配置提交或共享区服更新记录，当前客户端文件保持原样。
- 已下载量核验完整缓存的哈希，也计入有效断点；同大小损坏文件不会显示为已完成。

## 正式更新与差分

正式版发布后，安装器刷新分支和清单，以 MD5 和大小构成内容身份，搜索剩余网络字节最少的差分路径。路径成本扣除已校验缓存及有效断点；已生成并校验的中间版本也能作为起点。完整文件再次校验后移入正式临时路径；有效的部分完整文件可迁移并继续 Range 续传。

差分包和源文件先通过大小及 MD5 检查，再以固定内存窗口合成中间版本；每一段输出都必须通过官方目标哈希，最后才替换对应的游戏文件。取消后保留可验证的中间内容，安装版本只在全部更新完成后提交。包传输沿用网络工作线程，合成与验证使用单独的本地工作线程。

大小接口和进度统计使用实际选定方案的传输字节，已下载量包括可复用缓存和断点。磁盘调度另外预留补丁下载、相邻两段输出及共享内容的空间；已在缓存中的补丁也必须经过空间调度。完成一段后释放不再使用的中间输出，共享补丁和输出在最后一个使用者完成后释放。

当前差分解码器是编译进 `NTE.dll` 的 C# 实现，支持实际观察到的 **无外部压缩 HDIFF13**，参考上游 MIT 许可的 [HPatch 实现](https://github.com/sisong/HDiffPatch/blob/master/libHDiffPatch/HPatch/patch.c)，未引入独立的 hdiff DLL 或 NuGet 库。损坏的缓存补丁会重新下载；普通更新也可以下载或继续未完成的差分。未知格式、合成输出不匹配或旧文件变化会回退到完整资源下载，并相应更新进度及磁盘预算。普通磁盘读写错误直接报告，避免将空间或权限故障误当成差分失败而下载整个资源。

国服跨大版本分支提交只允许转入已安装官方配置此前公布的 `PreReleaseBranch`，并核对预告版本，不能任意改写分支。全部资源通过检查后才同步正式版本。差分合成失败或取消不会将未验证结果替换进客户端。

## 验证

普通回归覆盖公共 ABI 委托入口、大小与已下载量、取消续传、状态撤回、元数据不一致、缓存与旧文件损坏、跨分支和跨预下载版本复用、无预下载时的直接差分、补丁链取消后从中间版本恢复、三段合成空间及缓存任务的磁盘调度。`Fixtures/Hdiff` 的独立样本由上游 `hdiffz` 生成、`hpatchz` 再次应用后固化；测试本身不需要参考程序。`Fixtures/ReleaseTransition` 复现本次官方 11.10 GiB 更新及 9 条缓存补丁链。

显式联网检查：

```powershell
dotnet tests/Hi3Helper.Plugin.NTE.Tests/bin/x64/Release/net10.0/Hi3Helper.Plugin.NTE.Tests.dll -class '*LivePreloadTests' -explicit only
```

发布后可通过已有原生审计器检查 NativeAOT 的版本、可用状态和大小接口：

```powershell
dotnet tools/NteMediaAudit/bin/x64/Release/net10.0/NteMediaAudit.dll <NTE.dll> <新报告路径> 0 --preload-info
```

`--preload-info` 仅创建空 EXE 夹具。对现有安装只读核验实际更新计划：

```powershell
dotnet tools/NteMediaAudit/bin/x64/Release/net10.0/NteMediaAudit.dll <NTE.dll> <报告路径> 0 --update-info <游戏目录>
```

该模式通过原生 COM 大小接口校验实际缓存，记录计划传输量、已缓存量、剩余网络字节和安装文件指纹，不启动更新。显式 `LocalUpdateAuditTests` 还支持用已保存的官方配置及清单只读核验本机安装；只有设置 `NTE_UPDATE_PATCH_SAMPLE=1` 才会在证据目录下载并合成真实补丁样本，游戏目录只读。完整更新、Collapse 实际交互和游戏进入仍需分别验收。
